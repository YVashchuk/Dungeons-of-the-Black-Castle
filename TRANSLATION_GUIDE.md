# 🌍 Руководство по локализации (i18n)

Как устроена локализация «Подземелий Чёрного замка» и как добавить новый язык (EN / FR / UK / …).

Схема введена в Phase 2 (инкременты 2a–2c + shell): реестр локалей с переключением на лету, сохранением выбора и живой перерисовкой, плюс отдельный слой для статической UI-обвязки. Русский (`ru`) — **эталонная локаль и жёсткий fallback**.

---

## 1. Принцип

Весь показываемый текст берётся из объекта локали через резолверы. Каждый резолвер ищет ключ в **три шага**:

```
активная локаль (ACTIVE_LOCALE)  →  русская локаль (LOCALE_RU)  →  сам ключ (как строка)
```

Следствие: **неполная локаль безопасна** — любой непереведённый ключ автоматически показывается по-русски, а не ломает игру. До сырого ключа дело доходит только если строки нет и в RU (то есть ключ вообще не заведён).

Движок (`src/game_logic.js`) **не содержит захардкоженного текста интерфейса** — ни кириллицы, ни латиницы (инвариант 6c-1, проверяется харнессом). Любая новая UI-строка обязана идти через локаль.

---

## 2. Из чего состоит система

| Часть | Где | Что делает |
|---|---|---|
| Файлы локалей | `src/locale.<code>.js` | Определяют `const LOCALE_<CODE> = { … }` — все строки языка |
| Реестр `LOCALES` | `src/game_logic.js` | `const LOCALES = {}` + IIFE регистрирует каждую локаль по коду |
| Резолверы | `src/game_logic.js` | `pText` / `label` / `locSec` (текст параграфа + подписи выборов), `spellText`, `allyText`, `enemyName`, `t` (строки UI), `prefaceText` / `pregameText` — все читают `ACTIVE_LOCALE` с откатом на RU |
| Переключение | `src/game_logic.js` | `setLanguage(code)` → `applyLang` → `repaintAfterLangSwitch` (перерисовка карты, преамбул, пикеров, статической обвязки и текущего экрана) |
| Сохранение выбора | `src/game_logic.js` | `localStorage` под ключом `blackcastle-lang`; при загрузке — `loadSavedLang()` |
| Пикер языка | `src/game_logic.js` + `src/game_shell_top.html` | `renderLangPicker()` строит кнопки из `availableLangs()`, подпись — эндоним `langName`; контейнеры `#lang-pick-title` (старт) и `#lang-pick-menu` (меню). Минимальный, будет переработан при редизайне UI (реестр `group_68`) |
| Слой обвязки | `src/game_shell_top.html` + `applyStaticI18n()` | Статические элементы оболочки помечены `data-i18n` / `data-i18n-html` / `data-i18n-ph` / `data-i18n-title`; `applyStaticI18n()` проставляет их через `t()` при загрузке и при каждой смене языка (плюс `document.title` и `documentElement.lang`) |
| Сборка | `build.sh` | Склеивает `src/*` в единый HTML; порядок фиксирован, `locale.ru.js` идёт **до** `game_logic.js` |

**Важно про боевой интерфейс:** подписи боевых кнопок и HUD движок ставит динамически через `t()` из тех же `ui`-ключей — они локализуются автоматически, как только переведён раздел `ui`. Смена языка **во время боя** не поддерживается (подписи резолвятся в начале боя); пикер до боевого оверлея всё равно недоступен.

## 3. Форма объекта локали

`LOCALE_RU` (эталон) — это `src/locale.ru.js`. Верхнеуровневые ключи (порядок как в файле):

| Ключ | Тип | Содержимое | Переводить? |
|---|---|---|---|
| `langName` | строка | Эндоним языка (самоназвание): `"Русский"`, `"English"`, `"Français"`, `"Українська"` | да |
| `spells` | объект | 8 записей по ID заклятия (`LEVITATION`, `FIRE`, …), каждая `{ "name": "…", "full": "…" }` | значения — да, **ID-ключи — нет** |
| `allies` | объект | 2 записи (`magic_bell`, `bear_amulet`), каждая `{ "name": "…", "verb": "…" }` | значения — да, ключи — нет |
| `preface` | строка | Предисловие. Абзацы разделены `\n\n` (движок бьёт на `<p>` по этому разделителю) | да, **сохранив `\n\n`** |
| `pregame` | строка | Вступление «в путь». Тоже `\n\n`-абзацы | да, сохранив `\n\n` |
| `ui` | объект | 298 плоских записей `ключ → строка`. Две группы (см. ниже) | значения — да, ключи — нет |
| `enemies` | объект | 65 записей `ID врага → отображаемое имя` (строка) | значения — да, ключи — нет |
| `map` | объект | 43 записи `ID узла/слоя → название` (строка) | значения — да, ключи — нет |
| `p` | объект | 1221 запись `номер параграфа → { t, c }` (см. ниже) | `t` и подписи в `c` — да |

### 3.1. Параграфы (`p`)

Ключ — номер параграфа в виде строки (`"1"` … `"1220"`). Значение:

```js
"372": {
  "t": "Текст параграфа целиком…",        // проза, показывается игроку
  "c": [ "Подпись выбора №0", "Подпись выбора №1" ]  // массив строк
}
```

- `c` — **массив строк-подписей выборов**, выровненный **по позиции** с массивом выборов того же параграфа в `src/game_structure.js`. Элемент `c[0]` — подпись первого выбора, `c[1]` — второго и т.д.
- **Нельзя** менять длину или порядок `c`: подписи привязаны позиционно к структуре переходов. Не добавляйте, не удаляйте и не переставляйте элементы — переводите только текст на месте.
- 58 терминальных параграфов (гибели, победа §1220) не имеют `c` (или он пустой) — у них нет выборов.

### 3.2. Раздел `ui`

Плоский объект `ключ → строка`, две группы:

1. **Строки движка** (транслитерированные ключи: `geroy`, `sudba_opredelena`, `iz`, `oshibka_zagruzki`, …) — подписи, сообщения, alert-ы, которые движок вставляет через `t()`.
2. **Обвязка оболочки** — 77 ключей с префиксом **`ui_`** (`ui_btn_new`, `ui_stat_skill`, `ui_map_title`, `ui_menu_export`, `ui_doc_title`, …), соответствующие атрибутам `data-i18n*` в `src/game_shell_top.html`.

**Четыре `ui_`-ключа содержат HTML-разметку** (они помечены `data-i18n-html`) — в них есть теги, которые нужно **сохранить**:

- `ui_stat_skill_desc`, `ui_stat_stamina_desc`, `ui_stat_luck_desc` — содержат `<br>`;
- `ui_spells_intro` — содержит `<p>`, `<b>` и инлайновые стили.

Переводите только человекочитаемый текст, оставляя теги на местах.

## 4. Добавление нового языка (пошагово)

Пример — английский (`en`).

**Шаг 1. Создать файл локали.** Скопировать `src/locale.ru.js` → `src/locale.en.js`. В новом файле:
- переименовать константу: `const LOCALE_RU = {` → `const LOCALE_EN = {`;
- задать эндоним: `"langName": "English"`.

**Шаг 2. Перевести значения.** Перевести **только строковые значения**, сохраняя:
- все ключи (ID заклятий/врагов/узлов, номера параграфов, `ui`-ключи) — **не трогать**;
- структуру объекта и длину/порядок массивов `c` (см. 3.1);
- HTML-теги в `ui_*_desc` и `ui_spells_intro` (см. 3.2), разделители `\n\n` в `preface`/`pregame`, ссылки вида `§372` и числа.

**Шаг 3. Зарегистрировать в реестре.** В `src/game_logic.js`, рядом с определением `LOCALES`, расширить IIFE-регистрацию:

```js
const LOCALES = {};
(function(){
  if(typeof LOCALE_RU!=='undefined') LOCALES.ru=LOCALE_RU;
  if(typeof LOCALE_EN!=='undefined') LOCALES.en=LOCALE_EN;   // ← добавить
})();
```

Пикер и `availableLangs()` подхватят язык автоматически.

**Шаг 4. Добавить в сборку.** В `build.sh`:
- в массив `REQUIRED_FILES` добавить `locale.en.js`;
- в шаге 2 (конкатенация) добавить `cat "$SRC_DIR/locale.en.js"` **сразу после** `locale.ru.js` (и до `game_logic.js` — движок читает `LOCALES` последним).

**Шаг 5. Собрать и проверить.**

```bash
bash build.sh
node --check src/locale.en.js
```

Открыть билд, переключить язык пикером, пройти ключевые экраны (титул → создание → заклятия → преамбула → игра → бой → карта → меню → концовки).

## 5. Рабочий процесс перевода

Текст локали большой (проза 1221 параграфа + преамбулы + UI). Практический конвейер:

1. **Нарезка.** Разбить строки на куски ≤ 5000 символов.
2. **Черновой перевод.** Прогнать через Promt (translate.ru) или аналог.
3. **Ревью.** Вычитать через Gemini / ChatGPT и вручную, сверяясь со смыслом параграфа.
4. **Контроль формата** при переводе беречь: ключи, длину/порядок `c`, HTML-теги, `\n\n`, `§`-ссылки, числа, имена собственные (Барлад Дэрт, Майлин, Зачарованный лес — с учётом сложившейся передачи в целевом языке).

Так как непереведённые ключи безопасно откатываются на русский, локаль можно наполнять **инкрементально**: сначала `ui` + преамбулы (быстрый видимый эффект), затем проза `p` по частям.

## 6. Инварианты и подводные камни

- **Fallback безопасен, но односторонний.** Отсутствующий ключ → RU → сырой ключ. Если строка «выпадает» на русском в другом языке — ключ не переведён (или отсутствует).
- **`c` привязан позиционно** к `game_structure.js`. Не менять длину/порядок.
- **Никакой захардкоженной UI-строки в `game_logic.js`.** Любой новый текст интерфейса — только через локаль (`t()` + `ui`-ключ) и, для статической оболочки, через `data-i18n*`. Иначе строка не переключится и сломается инвариант 6c-1.
- **HTML в локали.** `data-i18n-html`-ключи содержат теги — сохранять при переводе.
- **Оболочка хранит RU как запасной вариант** прямо в HTML; `applyStaticI18n()` перекрывает его переводом при загрузке и при смене языка. Значение в локали — источник истины.
- **Бой/HUD** локализуются автоматически из `ui`; переключение языка в бою не поддерживается.
- **Эндоним — в данных.** `langName` живёт в локали (кириллица/латиница там допустимы), а не в движке.

## 7. Проверка

- `node --check src/locale.<code>.js` — синтаксис.
- Харнессы (каталог `_audit_tmp`, вне репозитория): форма локали (`_locale_shape`), покрытие/round-trip обвязки (`p2_shell_i18n_harness` — все `data-i18n*`-ключи существуют в `ui`), плюс полный регрессионный набор Phase 1/2.
- `bash build.sh` — сборка; в билде должны присутствовать атрибуты `data-i18n*`, `applyStaticI18n` и ключи `ui_`.
- Структурная база: 1221 параграф / 1205 достижимых (не зависит от локали, но должна держаться).
