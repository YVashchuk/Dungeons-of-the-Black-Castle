## C14: кнопка закрытия карты и критерий шрифта

**Конкретный дефект в архиве:**

- `game_shell_top.html:802` кнопка Close — просто `<button onclick=... data-i18n=...>`, **без class="btn"**.
- `:411` `.map-toolbar button` задаёт фон, рамку, размер12px, отступы, но **не font-family**.
- Общая `.btn` получает `font-family:var(--font-ui)` на`:82`; кнопки меню имеют `.btn`.
- Кнопки zoom/reset/fullscreen находятся в `.map-controls`, и их собственное правило`:404` задаёт `font-family:var(--font-ui)`.
- Поэтому Close не подключён к Forum/Cinzel и оставлен на **UA default font**. Конкретное имя Arial подтверждается только computed style текущего браузера; архив сам по себе не гарантирует Arial на любой ОС.

Минимальный предлагаемый патч:

```css
.map-toolbar button {
  font-family: var(--font-ui);
  font-weight: 400;
}
```

При переработке map-header назначить новый `.map-close` тем же token. Это отдельное упущение оформления; не доказательство, что Forum вообще не загрузился.

**Неоднозначность C14:** бриф говорит «headings and buttons» и regular weight, но код намеренно различает display/control и reading text:

1. Заголовки и `.btn`/map-controls: `--font-ui` = Cinzel→Forum→Cormorant Garamond→serif. Кириллические буквы должны разрешаться в Forum, латиница в Cinzel.
2. `.choice-btn` (`game_shell_top.html:258–260`) сознательно использует `--font-text` (Cormorant Garamond), размер23px/вес500, потому что действия — продолжение чтения. Буквальный критерий «все кнопки Forum» конфликтует с текущим дизайном UI-11. Это **чеклист нуждается в уточнении**, не причина глобально заменять reading font.
3. `fonts.css:34–38` Cinzel Decorative поставляется статическим Bold700, явно отражено group84 CU-19 DONE. Условие «все заголовки regular» нельзя переносить на этот декоративный титульный face. Обычные modal h2 уже400 (`game_shell_top.html:271`).
4. Forum объявлен только400 (`fonts.css:79–85`); `.sp-name` в picker inline500 (`game_logic.js:341`). Если браузер синтезирует жирность, это проверяется отдельно по rendered face/font weight. При выборе политики regular явно400 для UI heading, но не сбрасывать случайно Cormorant500 у читательских действий.
5. `getComputedStyle(...).fontFamily` показывает стек, **не реальный glyph font**. Стек с Cinzel первым в RU нормален: Cyrillic диапазон попадает в Forum через font fallback. Наличие Forum в CSS или значение `.fontFamily` не равны доказательству, что текущие буквы им нарисованы.

Практичный итог C14: **частичный FAIL для map Close**, если живой браузер подтверждает UA font; основная цепочка Cyrillic/Latin — отдельно PASS или BLOCKED по фактическим доказательствам. Прямое требование «все button Forum/Cinzel» пометить UNCLEAR/spec-scope; уточнённый критерий: «UI chrome/headings use UI face; narrative choice labels use reading face; no unintended OS default font».
