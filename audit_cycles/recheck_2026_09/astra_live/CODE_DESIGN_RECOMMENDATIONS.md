## Расчёт карточки заклятий

В сценарии **412 CSS px**:

- `.sp-wrap` оставляет `412 − 16 − 16 = 380px`.
- Границы карточки2px, внутренние отступы40px, иконка38px, два gap по14px, счётчик130px.
- Для описания остаётся **380 − 2 − 40 − 38 − 28 − 130 = 142px**, около37% ширины карточки. При360px —90px. Эти числа получены из CSS, не из браузерных измерений пользователя.

Перевод описания в отдельную строку на всю внутреннюю ширину даст338px при412px — примерно **2,38 раза** больше места для строки без уменьшения текста или областей нажатия.

Выведенные через repr `\u202f` и `\xa0` — корректные символы неразрывных пробелов, **не буквальные escape-ошибки**: проверка фактических символов сняла эту гипотезу.

Предпочтительны целые локализованные шаблоны, а не склейка частей предложений:

```js

## Предлагаемые исправления — не применены

### 1. Пропорции титульного изображения

Небольшой безусловно полезный патч к существующему правилу — сохранять рисунок внутри рамки:

```css
.t-rider-col img {
  object-fit: contain;
  object-position: center;
}
```

С этим сохраняется весь рисунок, но могут появиться боковые поля. Для действительно компактного мобильного титула лучше явная рамка и осознанное кадрирование:

```css
@media (max-width: 700px) {
  #scr-title { justify-content: flex-start; overflow-y: auto; }
  .t-rider-col {
    width: 100%;
    height: clamp(150px, 28dvh, 240px);
    overflow: hidden;
  }
  .t-rider-col img {
    width: 100%;
    max-width: none;
    height: 100%;
    max-height: none;
    object-fit: cover;
    object-position: 50% 48%;
  }
}
```

Это **кадрирование**, а не полный показ портретного исходника. Фокус48% — начальная дизайнерская гипотеза, его нужно подобрать визуально; небольшого `object-fit:contain` достаточно, если обрезка нежелательна. Короткий viewport также должен сохранять доступ к началу/продолжению игры. В скриншоте автор повторяется обычной надписью и внутри изображения lettering — это отдельный совет убрать дублирование после проверки title asset; не новая сюжетная ошибка.

### 2. Карточка: описание во всю ширину

В `renderSpellSel` убрать inline layout у карточки, явно разделить заголовок и описание. Сохранить нынешние `data-id`, `data-d`, обработчики, aria-label и disabled:

<div class="sp-card">
  <div class="sp-card-head">
    <span class="sp-icon" aria-hidden="true">…</span>
    <div class="sp-name">Слабость</div>
    <div class="sp-qty"><!-- те же − / число / + --></div>
  </div>
  <div class="sp-desc">Сделает вашего врага неуклюжим…</div>
</div>
```

```css
.sp-card-head {
  display: grid;
  grid-template-columns: 32px minmax(0, 1fr) auto;
  align-items: center;
  gap: 10px;
}
.sp-card .sp-desc { margin-top: 12px; }
.sp-qty { flex-shrink: 0; }
.qty-btn { min-width: 44px; min-height: 44px; }
@media (max-width: 390px) {
  .sp-card-head { grid-template-columns: 32px minmax(0, 1fr); }

```

При390px и ниже управление переносится в свою строку; описание всё равно занимает всю ширину. Не исправлять проблему уменьшением44px-кнопок. Для быстрых корректировок без новой разметки можно использовать `display:contents` у старой текстовой обёртки, но явные классы проще поддерживать и проверять.

### 3. Карта: закреплённая верхняя строка с Close

Перенести существующий заголовок с его `id="map-modal-title"` и существующую кнопку закрытия в один общий header, **не дублировать** их. Держать header первым дочерним элементом сетки, карту — в `minmax(0,1fr)`; объяснение/легенду спрятать в раскрываемое «Обозначения». Существующий `closeModal('overlay-map')` и controller focus-return сохранить.

```html
<header class="map-dialog-header">
  <h2 id="map-modal-title" data-i18n="ui_map_title">Карта приключения</h2>
  <button type="button" onclick="closeModal('overlay-map')"

```

```css

  gap: 12px;
}
.map-dialog-header h2 { min-width: 0; margin: 0; }

Текст `stub-сегментами` в пользовательской справке заменить на «короткими пунктирными ответвлениями».

### 4. Висячий отступ у действия со стрелкой

Проблему нельзя решить повторным `text-align:left`, он уже есть. Один безопасный CSS-подход — отдельное пространство для стрелки:

```css
#c-list .choice-btn {
  position: relative;
  padding-inline-start: 2.5em;
  text-align: start;
}
#c-list .choice-btn:hover { padding-inline-start: 2.5em; }
#c-list .choice-btn::before {
  position: absolute;
  inset-inline-start: .8em;
  margin: 0;
}
```

После патча проверить baseline стрелки; если браузер располагает absolute pseudo выше нужного, явно добавить одинаковую переменную вертикального padding и `inset-block-start`. Вариант с `<span class="choice-label">` и CSS grid `auto minmax(0,1fr)` надёжнее для сложного состава кнопки, но требует менять все её генераторы. Не затрагивать `.riddle-submit`, которой нужна собственная разметка; scope `#c-list` предпочтительнее глобального button.

### 5. Семантика цвета

Минимальный текущий патч ровно к журналу:

```css
.combat-log .hit  { color: var(--green2); }
.combat-log .miss { color: var(--red2); }
```

Красная шкала здоровья врага, красное оформление карточки врага и золотая победа — отдельные смыслы, их не надо глобально инвертировать. В дальнейшем классы `damage-to-enemy` / `damage-to-hero` яснее, чем `hit` / `miss`: нынешний `miss` обозначает не промах, а попадание по игроку. В тексте обязательно сохранить получателя урона и числовое изменение, чтобы цвет не был единственным носителем смысла.

### 6. Отдельная нижняя кнопка «Удар!»

Предпочтительно **переместить кнопку в DOM после группы заклятий**, а не только назначить CSS `order`: тогда визуальный порядок и Tab-порядок совпадут. Сохранить `id="btn-combat-round"` и handler — их использует движок и controller initial-focus.

```html
<div id="combat-buttons">
  <div class="combat-spell-actions"><!-- существующие кнопки способностей --></div>
  <div class="combat-primary-action">
    <button class="btn btn-p" id="btn-combat-round" onclick="combatRound()">Удар!</button>
  </div>
</div>
```

```css
#combat-buttons { display: grid; gap: 12px; }
.combat-spell-actions { display: flex; flex-wrap: wrap; gap: 10px; justify-content: center; }
.combat-primary-action { display: flex; justify-content: center; }
@media (max-width: 700px) {
  .combat-spell-actions { flex-direction: column; align-items: stretch; }
  .combat-primary-action .btn { width: min(100%, 280px); min-height: 48px; }
}
```

Удалить старый inline `display:flex` с `#combat-buttons`, иначе он выиграет у нового CSS. Вместе с разметкой необходимо обновить **два динамических места**: `game_logic.js:1785–1798` сейчас добавляет `combat-buttons-extra` к родителю контейнера, а `:2664` добавляет условную кнопку к родителю Удара. Добавить `id="combat-secondary-actions"` на группу способностей и явно добавлять оба типа дополнительных кнопок туда; иначе новая обёртка поместит условный выход рядом с Ударом. Существующее удаление по id в `clearCombatExtraButtons:1776–1780` сохранится. Проверить disabled/hidden состояния и превращение Удара в Продолжить/Конец (`endCombat:2808–2857`), а также повторный старт боя. Удар на отдельной нижней строке можно сделать sticky только после проверки, что он не перекрывает журнал и последние опции на коротком landscape-экране.

## Дополнительные советы по коду и дизайну

1. **Не переписывать приложение на новый framework ради этих дефектов.** Исправления локальны: title-art, spell-card, choice-button, map-dialog, combat-log/actions. Сохранять существующие семантические IDs и canonical data.
2. **Разделить текст боевого события и его оформление.** Генерировать один объект события `{type, actor, target, damage, remaining}`; locale formatter возвращает полный текст, CSS-класс выбирается из type. Сейчас несколько грамматических и цветовых проблем порождены склейкой фрагментов и двусмысленными class names.
3. **Постепенно вынести layout из inline `cssText` в классы.** Реестр UI-12 уже OPEN; это реализация существующего долга, не новая находка. Начать с трёх конкретных мест338/709/775, которые мешают мобильным исправлениям. Состояние вроде ширины HP и видимости оставить управляемым JS.
4. **У журнала один append API.** Реестр UA-03 сообщает51 место `innerHTML +=`; current observer вынужден отслеживать перестройку детей. `appendCombatEvent()` с DOM append и локализованным полным сообщением позволит контролировать цвет, грамматику и live-announcement в одном месте. Не делать новый `aria-live` на весь накопленный лог — будет повторно читать всю историю.
5. **Матрица проверки должна измерять реальный layout, а не только наличие CSS.** Минимум360/393/412 CSS px portrait,915×412 landscape, desktop; RU/EN/FR/UK; масштаб текста125–150%; длинная карточка Копии, длинное действие1193, карта с1узлом и насыщенная карта, бой с4+врагами. Указать реальный viewport и visualViewport в evidence. Не объявлять физический Pixel7a проверенным на основании desktop screenshot.
6. **Проверить поведение viewport с открытой адресной строкой.** `dvh` для модалок, safe-area для фиксированных элементов; не использовать высоту скриншота вместе с системными полосами как CSS высоту окна.
7. **Сделать начало игры короче по высоте.** Одна подпись автора, компактный hero-art, заголовок и главная CTA в первом экране; история/предисловие ниже отдельным действием. Это дизайн-рекомендация, не изменение канона.
8. **Короткий URL:** перенос всей игры/переименование репозитория не обязательны. **Корневой `index.html` уже существует** и содержит meta-refresh/canonical на `dist/dungeons-of-the-black-castle.html` (архив `index.html:3–4`). Поэтому адрес `/Dungeons-of-the-Black-Castle/` уже является предусмотренным коротким входом; создавать такой redirect заново не требуется. Отдельная живая проверка этого URL ограничена исходным разрешённым URL и в этом read-only разборе не выполнялась. Для желаемого `/DotBC/` нужен отдельный alias Pages-проект/папка под пользовательским сайтом либо согласованное переименование репозитория. Короткий alias, который перенаправляет на нынешнюю игру в том же origin/path, сохраняет существующий механизм сохранений и относительные ресурсы. Не обещать, что изменение `<title>` сократит URL. В отчёте достаточно предложить redirect-код; публикация не выполняется.
9. **Текущую интерактивную карту не подменять красивой иллюстрацией.** Art — фон/легенда, а topology, текущий узел и пройденные пути — детерминированный SVG поверх него. Если рисовать концепт, явно назвать его иллюстративным, без утверждения о канонической географии. Декоративная карта должна сохранять читаемость small-screen, контраст маркеров и отсутствие спойлеров.

Предложение редиректа для отдельного короткого alias (не применено):

```html
<!doctype html>
<meta charset="utf-8">
<title>DotBC — Подземелья Чёрного замка</title>
<script>
  const destination = new URL('/Dungeons-of-the-Black-Castle/dist/dungeons-of-the-black-castle.html', location.origin);
  destination.search = location.search;
  destination.hash = location.hash;
  location.replace(destination.href);
</script>
<a href="/Dungeons-of-the-Black-Castle/dist/dungeons-of-the-black-castle.html">Открыть игру</a>
```

Перед внедрением алиаса проверить семантику #N: нынешний game loader трактует hash как тестовую подготовку; публичный короткий URL без хеша — предпочтительный линк начала игры. Пользовательский короткий путь сохранит query/hash только как совместимость, а не как приглашение открывать тестовые параграфы.
