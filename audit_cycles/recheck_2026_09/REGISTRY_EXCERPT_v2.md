### UA-01_dialog_stack_dom_order - P1 - DONE
- **hypothesis (auditor):** _bcTopDialog() returns the LAST '.modal-overlay.on, .end-overlay.on' element in DOM order, not the most recently opened dialog. #overlay-sheet sits at the end of <body>, after #overlay-map, so opening the map while a bottom sheet is open makes Escape and the Tab trap operate on the sheet instead of the map. Suggested fix: keep an explicit open-order stack (push in _bcDialogOpened, pop in _bcDialogClosed) and return its top.
- **resolution (spec):** CONFIRMED, severity re-adjudicated to P2: the only reachable trigger is the M hotkey with a bottom sheet open, and because every .modal-overlay shared z-index 100 the later-in-DOM sheet also PAINTED on top, so Escape closing the sheet first was visually consistent - the real defect was keyboard focus landing on the obscured map. Fix: the controller keeps an explicit open-order stack (_bcDialogStack). _bcDialogOpened pushes the dialog and raises a .modal-overlay's inline z-index to 100 + depth so the newest dialog also paints on top; _bcDialogClosed pops and clears the inline z-index; _bcTopDialog returns the topmost stack entry that is still open (the DOM-order query stays as a fallback). .end-overlay keeps its own z-index 200. Result: paint order == focus / Escape / Tab-trap order == opening order for any dialog combination.
